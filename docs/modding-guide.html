01 版本与适用范围

这条路线针对研究样本中的 Windows x64、Unity 2022.3.62f2、IL2CPP 和 Direct3D 12，以莉特莉丝「绮夜寐影」为目标。资源提取用于识别、比对和制作。当前公开运行方式在 D3D12 绘制层生效，由用户按管理器流程启动自己的游戏。做离线研究时，保持客户端安装和已有游戏会话只读。

里芙、卡芙卡、坎特蕾拉、伊芙的 2B 联动服 跨游戏模型、材质、蒙皮与表情映射 莉特莉丝的动作时序、实时姿态与原生绘制环境

02 读取资源与建立引用图

  1. 选样本。 从经过完整性检查的本地资源索引选择目标角色、衣装、特效和显式依赖。把包复制到研究目录，记录版本、输入摘要和依赖关系，复制后复核摘要。后续只读这批副本。
  2. 拆归档。 先读 UnityFS 的元数据、数据块与节点表。早期把受影响的首块直接送进标准 LZ4 会失败。参照公开的兼容读取实现验证处理顺序，兼容样本先恢复受影响块，再做正常 LZ4 解压。逐块核对预期长度，再按节点边界提取序列化对象及外部资源流。
  3. 解析对象。 用 Unity 对象读取工具沿 Prefab → Transform → Renderer → Mesh / Material → Texture / Shader 走引用。纹理像素也可能来自外部流或图集依赖。用归档、对象 ID 和引用关系定位，名字用于检索。
  4. 双份导出。 OBJ 和预览图供肉眼检查。原坐标、三角索引、UV、法线、骨骼索引和权重、绑定矩阵及引用另存为结构化数据。预览的坐标系换手会调整轴和三角绕序，原值仍保留。记录纹理的原尺寸与格式，涉及运行时替换时另核对完整 mip 链。带负值的半浮点通道保留浮点表示，避免预览 PNG 截断数据。
  5. 核对产物。 检查节点与面索引不越界、权重和与声明一致、原坐标和预览能互相核对。用原位材质查看图集方向、透明边、UV 岛和缺失依赖。抽样 117 个主包加 3 个图集依赖成功解码，得到 27 个资源组和 322 个网格，资源组与角色数不是同一统计口径。

解决了什么。 将解压失败、依赖缺失、引用串错和转换失真分开排查。一个 OBJ 能正常打开，只证明了网格预览。原生骨表、变换、表情和动画需要另行读取与核对。

下一套要留下什么。 本地输入清单、引用图、部件表和回读报告。把未能解码的变体、缺依赖和数据缺口列出来。不同客户端版本和资源类别要重新抽样验证。

03 从资源引用找到游戏里的绘制

离线引用告诉你哪个对象可能用一张图。要替换游戏画面，还要找到它真正提交的绘制及当时的状态。

  1. 设计正负场景。 固定角色、皮肤、动作和镜头，采目标外观、原皮及相邻角色。分别核对展示、普通动作、连续闪避和大招。特效至少对比施放前、命中、落地和消失后。
  2. 拼全一次绘制。 记录它提交时的 VS/PS（顶点／像素着色器）身份、PSO（管线状态对象）、根签名、根参数、描述符表、纹理视图、顶点流、索引范围、拓扑、渲染目标和深度模板。用动作和通道标注观察结果。
  3. 追踪描述符来源。 描述符地址的含义会随复制、堆切换、销毁和重用而变。记录复制链及资源代次，按当前命令列表和堆状态解释地址。还要核对视图和上传内容。仅凭同一个槽位、相同索引数或相同 Shader 无法确定归属。
  4. 拆开同一动作的多笔绘制。 颜色、深度、阴影、描边、眼睛遮罩和动作残影常由不同程序或状态提交。按各自的输入与生命周期建立规则，证据不足的路径保留原版。
  5. 收窄候选再回放。 用着色器和几何范围先排除无关绘制，再核对纹理来源、实际绑定与资源代次。把目标绘制和会误命中的对照一起放进回归。

解决了什么。 早期索引数匹配、旧缓存和绑定快照都曾造成误判。多流布局里某个槽的 stride 为零也不能直接判整笔绘制无效。按实际引用的流、描述符复制与绘制边界重新核对后，才建立了可用的候选范围。

04 拆分原版网格与制作原创衣装

原版角色的脸、头发和部分饰物可以独立，身体与衣装也可能共用 Body01、Body02 或同一张图集。

  • 忠实拆分。 按原三角面建立衣装、可见皮肤与混合边界组。每片保存原位置、原 UV、法线、骨权重和源面编号，必要时加顶点索引重排表。检查拆开再合并的几何、UV 与渲染结果。
  • 处理遮挡区。 如果衣服下面原本没有皮肤面，新增身体或接缝标为推定重建，与忠实分割分开存放。它可以作为合体参考，其来源与原版网格不同。
  • 制作衣装。 根据原角色体型和动作空间定版型，分开布片、带子、边缘与饰物，处理真实搭接和下层连续面。排 UV、做材质后，用正侧背和多个姿态检查肩、腰、腋、胯、肘、膝及发束接触。正面图无法证明厚度、下层遮盖和跨姿态净空。
  • 接入原生域。 按材质、通道和可用骨表分配衣装。用目标骨链驱动有依据的布片，在边缘过渡权重。衣摆随目标骨链摆动；完整的布料或头发物理要单独设计与验证。

真实例子。 「星潮晶华」验证了原创衣装可进入原生渲染流程。实机后发曾出现大块锯齿，因为改过的颜色网格与原描边使用了不同几何。修复为同帧、同目标的已确认描边绘制提供配对网格，并沿用原状态。静态渲染和 GLB 用于审阅，长步和深屈肘仍有局部接触，薄纱及部分光照效果有待打磨。

05 跨游戏模型与原生骨架

  1. 保留供体记录。 使用有权使用的供体，保留原 UV、三角面来源、材质、权重和形变。统一轴向、手系、单位和静置姿态，手系翻转时检查三角绕序和切线符号。
  2. 抽取目标骨架。 读取目标层级、静置矩阵与逆绑定矩阵。示例全身骨架为 336 骨，各个原生 Renderer 有自己的局部骨骼表。全局骨号必须转成对应分片的局部索引。
  3. 先对齐，再映射。 以髋肩、头颈、四肢链和手脚做静置对齐，保留可接受的造型比例。主骨按部位与作用映射，辅助骨按衣摆、发束或饰物用途处理。缺骨时选有证据的父骨或稳定锚点并记录降级。批量最近骨映射容易使肩袖、手指和发束跟错。
  4. 分片并修接缝。 按目标身体、头发、脸等绘制域分片。重合位置尽量使用一致权重，取两侧局部骨表交集，必要时重分域或在腰边渐变。保留 UV 岛、材质和源面映射。
  5. 编码并回读。 合并落在同一骨的权重，按目标布局保留至多四项并归一。对 UNorm8 权重按小数余量补足到总和 255，填充索引也要在合法骨表内。用编码后的实际数据回读静置、举臂和下蹲等离线姿态，检查裂缝、翻面、拉伸和量化误差。再在对应版本实机验证走动、连续闪避和大招。

真实故障。 早期跨游戏模型经过手系镜像后又多翻了一次三角绕序，颜色和描边用的剔除方向不同，展示页正面被灰红轮廓盖住。对照法线、索引和剔除模式逐域修正。卡芙卡的外衣与淡紫内衬有真实的反向面，保留供体内衬，去掉外层额外生成的反面，并单独处理内衬描边。只看静置模型无法证实这些通道在游戏里正确。

06 绑定表情与大招

骨骼负责较大尺度的动作，脸部 BlendShape 负责闭眼、嘴形、眉眼及局部变形。原皮形变差值按原网格顶点索引，供体的拓扑和顶点顺序通常不同。

  1. 找实际权重来源。 读取原脸通道、动作片段及演出用到的槽与时序，检查中性值、峰值和连续动作。需要运动输出时，保留原生当前及上一帧的表情权重、骨骼状态。
  2. 映射供体形变。 先按闭眼、眉形、口部等语义匹配已有形变。按绑姿变换位置差值并重算法线差值。没有合适形变时，按原版运动与供体局部拓扑制作候选，保护眼睑、内嘴、下颌及同位接缝，逐帧查翻面。缺依据的槽保留中性。
  3. 编码到分片。 按新网格和各分片的顶点顺序写数据。此适配使用 32 槽布局，只驱动已映射且身份已验证的槽。脸的颜色、深度、阴影、描边及运动输出都要使用对应形状。
  4. 眼睛单独检查。 仅在已确认眼部顶点上调虹膜与头、眼骨的权重。看转眼时是否穿出眼睑，闭眼后是否漏眼，独立瞳孔与高光是否符合原动作。
  5. 测相邻动作。 单次大招通过后，再测展示切大招、连续闪避、残影和回到站姿。近景闪回原脸时逐笔核对脸色、脸深度、脸阴影和头发遮罩。旧累计读取额度曾令后续大招和闪避误回退，改为逐帧控制、区分主镜头与阴影，并继续核对原生压缩标志和资源归属。

07 贴图、受光与战斗特效

原网格改色

红黑路线保留原模型和 UV。改色保持目标图集尺寸、格式、透明度与完整 mip 链。早期基础包的对应图集为 BC7，先用各 mip 的稀疏块快速排除错误输入，再对去掉上传行 padding 的紧密行内容计算完整 SHA-256。稀疏块用于排除，完整身份用于授权替换。

早期单卡在匹配的纹理上传阶段换数据，已上传的资源通常需要退出并重进才能恢复。六套热切换版的红黑观察原上传，在已确认的绘制中临时绑定改色图集和像素程序，随后恢复原绑定。因此可以在同一会话切回原版。

新网格材质

跨游戏模型按供体图、UV 平铺、材质色因子和透明规则烘页。已验证的高清路径把候选从 248 提升到 992 像素级，将 RGB 与原有透明覆盖分开。高分辨率 RGB 写入多级线性缓冲，像素程序按 UV 导数选 mip 并插值，alpha 仍取原紧凑材质路径。画面变清楚之后还要核对深度、阴影、描边、眼部遮罩和运动辅助输出，防止轮廓错位或闪避双影。发丝、掌指和 2B 的暗部优先用局部受光修正，保留原有的遮挡、亮部和裁切。

像素程序与 Light

  1. 从确切的特效绘制关联原生 VS/PS。光束、星芒、烟尘、碎片、残影、武器发光和 Light 分开检查。
  2. 为确认的原生程序制作候选。克隆原 PSO，保留原 VS、根签名、拓扑、混合、深度模板与辅助目标布局，只改需要的字段。保留透明、裁剪、动态发光与无关输出。
  3. 用材质常量、纹理尺寸和归属等条件限制目标分支。共用命中或场景资源必须增加作用范围证据。红黑对部分共享路径使用单人前台及目标衣装条件，来源不清楚的效果保留原色。
  4. 粒子颜色与 Light 分开。红黑从 Shader 反射与确切灯光颜色定位目标表面的主光、附加光计算。对已确认的源色处理线性与伽马输入，保留亮度和其他光色。Unity 场景里的 Light 对象、地面和其他角色继续使用原计算。
  5. 先做原生程序回放，再看实机里的命中、星芒、烟圈与落地。某一层改红仅证明这一层命中。红黑仍有未覆盖的技能及效果。

08 绘制事务与失败回退

运行时使用 ReShade 的 D3D12 分派及项目补丁。文件校验和逐笔绘制判断承担不同职责。

层次 需要证明什么 证据不足时
包与宿主 包文件摘要、组件合同、兼容版本及宿主身份 拒绝加载或保留原版
绘制来源 确切 VS/PS、根签名、拓扑、顶点布局和索引／顶点范围 跳过替换
资源归属 目标纹理视图、描述符堆与资源代次、所需 mip 身份、必要采样器 保持未就绪或非目标

状态恢复 PSO、输入装配、根绑定及动态状态恢复后与原快照相符 恢复存疑时冻结受影响记录，等命令列表重置

实际恢复涉及输入装配视图、字节偏移、stride、范围、PSO、根参数、描述符堆及必要动态状态。高清页或脸部路径需要在扩展根签名下重放原参数，再把原绑定恢复。原绘制回退的前提是状态仍然可信。

真实故障。 大招曾闪回原模型。一条独立可写深度的描边被套进了普通镜头的只读深度复用规则。修复为独立写入建立自己的确切身份，复用路径继续核对同一深度目标、层及资源代次。分支之间不能借用尚未证明的条件。

09 管理器、打包与会话热切换

  1. 包描述。 声明角色、皮肤、运行入口和清单。文件按相对路径组织，记录组件和载荷摘要。校验器拒绝缺件、摘要或合同不符、以及超出包范围的路径。
  2. 启动与兼容。 核对宿主身份、架构、Unity 分支与已确认的渲染来源。用户按管理器流程启动。工具按需申请权限，运行仍要通过图形守卫。启动修复包括提前创建所需目录，以及用有限查询和等待权限核对进程实例，避免因权限请求过宽误判退出。
  3. 观察与准备。 用户选目标后，当前外观继续工作；目标先观察原始绑定、准备资源。只让当前选中的组件提交替换。观察范围在命令列表开始／重置时确定，避免从一段已经录到一半的命令中推断完整状态。
  4. 提交切换。 合同、组件、会话及目标资源均就绪后，在主交换链呈现边界切换。未就绪保留当前外观，更新的请求可覆盖等待中的旧请求。租约失效撤销替换权限。
  5. 分派与恢复。 生命周期事件按需广播，高频绑定稳态只分派给当前外观，准备切换时最多涉及当前与目标。原模型稳态跳过这类分派。切回原模型恢复原版绘制并保留会话；已加载的图形组件可能驻留到游戏退出。
  6. 核对回执。 管理器发请求只是第一步。用游戏侧对同一运行实例的回执确认切换，再用画面检查外观、技能和战斗是否正确。六套之间及切回原皮后可继续换装，是本版热切换的实机目标。

10 如何查出并修复掉帧

曾出现启用 Mod 后明显掉帧，切回原皮仍掉帧。原皮状态的替换绘制计数已经为零，因此把排查移到驻留组件处理的常规图形事件上。

  1. 用同一地图、视角和帧率配置比较原版、启用适配与切回原模型。
  2. 用独立程序在同一适配器上比较系统 D3D12、旧 core 与新 core。关闭通用后处理，空置 addon 目录，执行同一批描述符复制。预热后比较多轮中位数。
  3. 旧 core 在互斥锁下查询描述符 CPU/GPU 地址时扫描 8192 个预分配堆槽位。将查找改为遍历紧凑的活跃堆列表，销毁时同步移除，保留地址边界、对齐、重叠拒绝、资源代次及事务核对。
  4. 用错地址、重叠区间、堆销毁、地址重用和复制事务回归，确认提速不会放宽资源身份条件。之后回原来的实机场景复测。
观测 修复前 修复后
隔离环境，一批 32 个描述符复制 约 111–118 微秒 约 1.8–1.9 微秒
曾掉帧的同一游戏场景 约 30 FPS 约 100–110 FPS

隔离对照定位的是一处 CPU 开销，游戏实测给出特定场景下的结果。其他硬件、地图、动作和客户端版本仍需测量。

11 怎样证明每一步有效

验证层 实际检查 可以得出的结论
静态与回读 原面、UV、索引范围、权重、绑定矩阵、贴图与 mip、导出 GLB 数据可读，结构和样本形态符合要求
原生回放 建立 D3D12 PSO，使用 WARP 软件回放，对比颜色、透明覆盖、深度、遮罩和辅助输出 已构造的输入及正负对照按规则执行
隔离硬件与包 独立 D3D12 宿主、真实呈现边界、篡改拒绝、资源代次重用及绑定恢复 夹具和对应硬件满足已测合同
游戏实测 展示、移动、连续闪避、大招、战斗后恢复、来回切换与性能对照 该客户端版本和测试场景下的可见结果

每个新增通道至少测 目标命中、其他角色拒绝、错材质拒绝、失效资源拒绝、切换和回退。单次截图覆盖不了动作时序，提交计数只说明走到某处。GLB 预览可以看模型与局部动作，游戏里的受光、布料和完整绑定须另验。记录版本、样本、场景条件和预期差异；对外只带脱敏结果。

12 复用流程做下一套 Mod

步骤 你要做的事 进入下一步前
1. 划范围 选一个角色、一套皮肤和一个可重复场景。先挑改色、模型或特效中的一项 写下目标和应保留原版的场景
2. 建资产表 提取目标与依赖，建立 Renderer、材质与纹理引用 用原材质正确回读，记录源面和 UV
3. 建绘制样本 追踪原 VS/PS、实际绑定、纹理视图和通道 同 Shader 的非目标样本被拒绝
4. 做最小修改 先挑一张图或一片网格，确认格式、索引、材质、骨表 软件回放出现预期差异，并通过恢复对照
5. 扩到动作 补面部、阴影、描边、遮眼、淡出和残影中已确认的通道 对应近景及动作切换没有混画或错层
6. 封包 为自己的角色与皮肤建立规则和相对路径清单 包校验、失败回退与资源就绪均可复查
7. 实机复测 核对原版、替换、切回及再切换 记录已验证场景、性能和未解决问题

一个例子。 想把新角色的发饰改色，先从发饰 Renderer 找到材质与图集页。挑一帧发饰可见的画面，找到对应绘制和实际上传。把同场景其他发饰或同 Shader 的物件作为负例。只改一块明显颜色，用 WARP 看目标是否改色、非目标及后续绘制是否保持原样，再到实机看展示和动作。若颜色正确、描边位置不对，查描边的几何与深度状态，并给它建立独立规则。
