# v0.1.2：启动权限与排障

管理器和运行器可以普通打开，也可以选择「以管理员身份运行」。助手只在实际需要时请求权限；不用为了使用本工具改变 UAC 设置。

## 正常启动

1. 完整解压发布包，打开 `LvmengModManager.exe`，选择自己的游戏本体 `Lumin.exe` 并保存。
2. 启用内置 Mod，打开运行器，再点击启动。
3. 如果 Windows 出现权限确认，由你决定是否继续。取消会结束本次启动；工具不会反复弹出确认。
4. 自动启动模式由工具按保存的方式启动客户端或启动器。手动模式先等待运行器提示助手已就绪、正在等待游戏，再从自己的官网或 TapTap 启动器正常进入。

手动模式下，先准备好助手再进入游戏。只打开管理器或运行器，还不等于助手已经就绪。游戏的登录操作仍由你在自己的启动器中完成。

## 不同打开方式如何处理

| 当前环境 | 启动行为 |
| --- | --- |
| 普通方式打开工具 | 沿用正常启动方式；助手需要权限时才请求提升。 |
| 管理员方式打开工具，桌面 Shell 是同用户、同会话的普通权限 | 自动启动优先通过该桌面上下文派发；助手按实际权限进入流程。 |
| 桌面本身已经高权限，例如 UAC 已关闭或整个桌面在高权限环境中 | 沿用实际环境权限并记录状态，不能保证创建普通权限的游戏进程。 |
| 没有桌面 Shell | 按当前可用环境权限处理并记录状态。 |
| 桌面 Shell 属于其他用户或其他会话 | 不向它派发启动；回到游戏所在桌面会话，用该桌面同一用户重新打开整个管理器。 |

工具不会为改变权限而关闭或开启 UAC，也不会要求你修改系统的安全设置。管理员打开管理器可以被接受，但 Windows 最终给游戏分配什么权限，仍取决于当前桌面和系统环境。

## 遇到提示时

| 提示或现象 | 处理方式 |
| --- | --- |
| 本次启动已取消 | 这是取消 Windows 权限确认后的结果。准备继续时，由你重新点击启动。 |
| 同用户、同会话的普通桌面启动桥接失败或超时 | 自动派发会停止，不静默改用管理员启动，也不循环重试。选择手动模式，重新等到助手就绪后，再从自己的启动器进入。 |
| 桌面用户或会话不匹配 | 回到游戏所在桌面会话，用该桌面同一用户重新打开整个管理器。手动模式不能保证绕过跨账号或跨会话的访问限制。 |
| 工具显示正在等待手动启动 | 从你自己的游戏启动器正常进入；无需修改 UAC。 |
| 提示客户端或包的校验失败 | 核对下载版本、完整解压状态及游戏位置。权限调整不会跳过客户端来源、运行包或资源校验。 |

用于开发排障的只读命令：

```text
LvmengModelTool.exe --probe-launch-privileges
```

该命令只记录当前权限环境到本机 `logs/launch_privileges_probe.json`，不请求管理员、不启动游戏、不调用加载器。诊断文件只留本地；其中的环境信息不属于公开发行资料。

## 关于调整 UAC 后旧版能够运行的反馈

有使用者反馈，调整权限相关设置后，旧版已经可以正常换肤；同时提到可能更改过默认管理员运行设置。缺少调整前后的进程令牌、兼容性选项和完整日志，不能据此确定是哪一项设置起了作用，也不能把这条旧版反馈当作 v0.1.2 的现场验收。

现代 Windows 中，通知滑块的「从不通知」不等于完全关闭 UAC；其分离令牌和自动提升行为仍可能存在，详见 [Microsoft 的 UAC 技术说明](https://learn.microsoft.com/en-us/windows/win32/secauthz/user-account-control)。工具按实际进程和桌面权限选择启动路径，不依赖该滑块的位置。无需为了本工具降低系统的 UAC 通知设置。

## 验证边界

v0.1.2 的权限修复处理工具入口、助手就绪和启动派发。编译、只读探测或离线路由验证不等于管理员实机验收，也不证明真实游戏登录、渲染绑定、全部技能、帧率和长期稳定性已经通过。

游戏更新兼容检查、运行包完整性校验及原有图形资源匹配继续执行。详细范围见[验证与限制](验证与限制.md)，客户端更新规则见[更新兼容策略](更新兼容策略.md)。
