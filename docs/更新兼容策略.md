# v0.1.1：官网版本与日常更新

旧版将四份客户端程序文件的完整摘要固定在旧渠道版本上。官网版本或游戏更新改变这些文件后，管理器会在打开运行器前报告“客户端版本不匹配”。

新版将这些摘要用作已知版本识别信息，同时独立验证实际渲染条件：

1. 选择的程序为游戏本体，游戏身份与 AMD64 PE32+ 架构匹配。
2. Unity 保持在已支持的 2022.3 分支。
3. 四份完整渲染来源的 SHA-256 匹配，包括基础数据、原生 Shader 包及目标角色纹理来源。
4. 按 Manifest 头内版本选择最新缓存，不看文件时间；校验最新完整缓存的 CRC、结构、依赖及关键包的 GUID/尺寸和实际文件摘要。旧缓存残留不会让新签名失配时回退放行。

普通 EXE、IL2CPP 或渠道程序更新后，只要上述渲染条件仍成立，可进入 compatible-update 状态，无需每次手改整份 EXE 哈希。引擎分支、资源来源或无法识别的 Manifest 格式变化仍会拒绝，并给出具体原因。

本地缓存不是服务器或游戏内活动包版本的证明。启动后的实际绘制仍须通过原有 VS/PS、完整 mip SHA、资源所有权、描述符代数和会话等条件；新的未知资源不会强套旧程序。本版没有宣称适用于所有未来更新，也没有增加新一轮完整游戏场景验收。

## 使用

更新管理器后保留已有设置。选择游戏安装位置，检查兼容状态，再打开运行器。官方版本若依赖启动器登录，可选择“手动启动游戏”：先在运行器中准备，再从自己的官方启动器正常进入游戏。正常退出旧游戏后再开始新一轮加载。

## 验证与隐私

官网与 TapTap 两个真实目录通过只读检查；22项兼容变异、12项独立 Manifest 检查、16项生产链与17项管理器检查通过。渲染核心、原生 addon、纹理与特效等74个固定文件保持原摘要。

公开 policy 仅含相对路径、公开游戏身份及资源摘要。本机安装位置、个人配置、账号或UID、登录/鉴权数据、会话日志和真实诊断不随 ZIP 或源码上传。图片与文件成员在发布前独立检查。
